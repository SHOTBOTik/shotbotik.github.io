Как я работаю

Весь код пишут нейросети — Claude Code. Я ставлю задачу, делю её на части и проверяю результат. План проходит критику, тесты по правилу пишутся до кода, перед вливанием — ревью и тесты.

  1. План

    Цель, части и у каждой свои файлы. Критерии приёмки такие, что на каждый можно ответить «да» или «нет».

  2. Критик плана

    Отдельный агент ищет, почему план сломается. План правлю до запуска.

  3. Тесты до кода

    Это правило процесса: красные тесты идут отдельным коммитом, исполнители их не меняют.

  4. git worktree ×4

    Команда агентов

    Части идут волнами, параллельно. У каждой своя ветка и свой git worktree.

  5. Ревью

    Агент со свежим взглядом смотрит дифф. Находки blocker и major исправляются до вливания.

  6. Проверки

    Тесты, e2e в браузере, скриншоты интерфейса против эталона.

  7. Влито

    Перед вливанием ставится метка отката, отчёт приходит мне.

пульт — пример сессии

Пример сессии в терминале: задача, план, критик плана, тесты до кода — красные, агенты ×4, каждый в своём git worktree, тесты зелёные, ревью, влито в main. После примера можно вводить команды: help, about, projects, skills, contact, clear.

JustLauncher

Suppy · сейчас01

JustLauncher

Лаунчер Minecraft. Делаем командой Suppy, сайт — justlauncher.org.

Моя зона: админка, бэкенд сайта и реклама, плюс тестирование и процессы.

Что сделано

Админка React, TypeScript

  • модерация жалоб и статей, журнал действий, фильтры, права ролей;
  • доска задач с зонами ответственности, ответственными и нагрузкой;
  • переделаны главная, «Мои задачи» и карточка сотрудника, добавлена история статусов задач;
  • редизайн и своя дизайн-система: Tailwind, графики на Recharts.

Статистика продукта — прямо в админке вместо Grafana

  • удержание, онлайн, воронки за любой период;
  • тяжёлые запросы к PostgreSQL переписаны, их планы разобраны через EXPLAIN;
  • у расчётов есть бюджет времени и кеш, прогрев идёт в фоне по расписанию;
  • аудит метрик дашборда Grafana на корректность.

Раздел «Реклама»

Отчёты Яндекс Директа через API, рядом с метриками продукта. Воронка «показ → клик → скачивание → первый запуск», данные обновляются каждый час.

Бэкенд сайта Kotlin, Spring, PostgreSQL

  • несколько сервисов: лента, посты и статьи, комментарии, модерация, доска задач;
  • миграции Liquibase;
  • интеграционные тесты на настоящем PostgreSQL;
  • защита от одновременных правок — оптимистическая блокировка;
  • описываю контракты API для фронтенда.

Тестирование

  • e2e-тесты интерфейса на Playwright, скриншоты сверяются с эталоном, проверки идут в GitLab CI;
  • разбор нестабильных тестов и нехватки памяти на CI;
  • исследовательское тестирование десктоп-клиента «как злой пользователь»: дефекты с шагами воспроизведения. Интерфейсом управлял через Windows UI Automation из PowerShell.

Процессы и выпуски

  • регламент приоритизации задач и оценки сроков для команды: баллы по критериям, у задачи один ответственный, размер и крайний срок. Сверен с практиками Linear, Kanban и Shape Up и встроен в доску задач;
  • выпуски сервисов через пайплайн GitLab: до запуска проверяю, переживут ли миграции старый код, после — живой сервис.

Реклама — с сентября 2026

  • Яндекс Директ: разбор поисковых запросов, минус-фразы;
  • цели и офлайн-конверсии в Яндекс Метрике: стратегия учится на первом запуске лаунчера, а не на клике; проверяю метки атрибуции;
  • считаю, во сколько обходится новый и вовлечённый игрок;
  • маркетинговый план по одной воронке: реклама → сайт → скачивание → первый запуск → удержание.

Пульт

Мой интерфейс поверх Claude Code. В нём я веду все свои проекты, и этот сайт тоже.

Моя часть: задача, архитектура, проверка и приёмка. Код пишут нейросети.

Что умеет
  • Окна по темам. У каждого окна своя память, правила и журнал. Сессии под капотом сменяются сами, нить переносится сводкой.
  • Память по ярусам: ядро, темы, архив. Её обновляет «хранитель» в фоне. Секреты лежат отдельно от памяти. Старые чаты Claude Code импортированы по окнам, секреты из них вычищены.
  • Задача с кодом: план приходит карточкой с кнопкой «Поехали», его проверяет критик плана; волна 0 — контракт и красные тесты, дальше части идут параллельно, каждая в своём git worktree; потом ревью и вливание с меткой отката; в конце отчёт и кнопки «Принять» / «Удалить».
  • Вливание — сразу, после ревью или через MR.
  • Лимиты подписки: учёт расхода по моделям и агентам, ожидание сброса лимита и автопробуждение.
  • Кэш промпта: замерил, как работают кэш промпта и автосжатие контекста Claude Code, и подстроил под это архитектуру. Лимиты подписки здесь — главная мера затрат.
  • Проверки: Vitest на сервере и клиенте, UI-проверки в headless-браузере со скриншотами, живые прогоны на дешёвой модели во временном каталоге.

Устройство

  • сервер на Node.js и TypeScript с Claude Agent SDK;
  • клиент на React, связь по WebSocket;
  • свои MCP-инструменты для агентов;
  • десктоп-оболочка на WebView2.

Работает на подписке Claude через Claude Code. Это личный инструмент, а не продукт.

  • MCP
  • WebSocket

Сервис повтора сделок

Сервис на Node.js повторяет сделки выбранных трейдеров через REST API биржи с подписью запросов.

Моя часть: задача, архитектура, проверка и приёмка. Код пишут нейросети.

Как устроен
  • отдельные процессы: источники данных пишут снимки, исполнитель по ним выставляет ордера;
  • «сторож» следит за остальными процессами: пульс, перезапуск зависших, алерты без дублей, периодическая сводка в лог;
  • надёжность: замки от двойного запуска, автоперезапуск, автозапуск через Планировщик Windows, ротация логов;
  • перед обновлением — сухой прогон без ордеров и повтор прошлых дней на сохранённой истории цен;
  • скрипт обновления можно запускать повторно без вреда, перед изменениями он делает бэкап;
  • новые версии прошли разборы, критику плана и код-ревью агентами.
